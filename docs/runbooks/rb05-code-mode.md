# RB05 用 Code Mode 跑编码任务

> 本文是通用机制 runbook；界面入口与文案以你的客户端为准，配套参考实现见 [implementations/openclaw/](../../implementations/openclaw/MAPPING.md)。

**一句话目的**：让员工通过 Code Mode（ACP 编码代理）承接编码任务，而不是走默认模型。

**适用场景**：写代码、改 bug、跑测试等开发类任务；或你明确想让编码代理接管执行时。

**前提准备**：已创建员工；知道 Code Mode 与默认模型互斥（界面也会给出类似"启用后将通过 Code Mode 运行，与模型互斥"的提示，参考实现文案）。

**操作步骤**（入口名称以你客户端里的实际入口为准）：

1. 新建或编辑员工时，开启"Code Mode"开关。预期：默认模型选项被置灰，提示二选一。
2. 保存并启用员工。预期：员工改由 codeagent / opencode 承载运行。
3. 按 RB02 给这名员工安装 codeagent 条目组的技能。预期：匹配的技能在能力清单里显示"已启用"。
4. 进入员工会话派编码任务。预期：回复由编码代理产出。
5. 想切回默认模型：编辑员工，关掉 Code Mode，再选一个默认模型。预期：保存后回到普通对话模式。

**你会看到什么（ACP 会话的特点）**：

- **过程实时可见**：ACP 编码代理干活时，会话里分三段实时流出——先是"思考"（它怎么拆解这个问题）、再是工具调用卡片（读了哪些文件、跑了哪些命令，一步一张）、最后是正文结论。默认模型会话没有这么细的过程视图，这是 Code Mode 最直观的体验差异。
- **会话由 ACP agent 管理**：这类会话不支持"压缩上下文"，界面会给出类似"这个会话由 ACP agent 管理，暂时没法手动压缩"的提示（参考实现文案）。上下文太满时的正确做法是拆任务或新建对话，不是硬撑。
- **Lite 版本**：参考实现的 Lite 版本默认启用 Code Mode 且可能不可切换（界面会给出类似"Lite 版本默认启用 Code Mode"的提示，参考实现文案）。

**怎么验证成了**：派一个"给某函数补单元测试"的任务，员工以编码代理身份产出可运行的测试代码；员工详情里运行方式显示为 Code Mode；会话里能看到思考与工具调用的过程流。

**常见问题**：

- Q：Code Mode 员工还消耗默认模型吗？A：不消耗，二者互斥，Code Mode 员工只走编码代理运行时。
- Q：Lite 版本为什么改不了？A：参考实现的 Lite 版本默认启用 Code Mode，可能不可切换。
- Q：Code Mode 会话上下文太多怎么办？A：ACP 会话不支持手动压缩（见"你会看到什么"一节），建议拆任务或新建对话。
