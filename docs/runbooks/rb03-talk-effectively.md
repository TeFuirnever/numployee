# RB03 和数字员工高效对话

> 本文是通用机制 runbook；界面入口与文案以你的客户端为准，配套参考实现见 [implementations/openclaw/](../../implementations/openclaw/MAPPING.md)。

**一句话目的**：用"说清目标 + 给足上下文 + 让它先追问"的三段式，让员工一次做对、少返工。

**适用场景**：经常要返工、答非所问，或觉得员工"不够聪明"的时候。

**前提准备**：已有一名启用中的数字员工（没有就先走 RB01）。

**操作步骤**：

1. 一句话说清目标，别只丢关键词。把"背景、要做什么、做成什么样"写进同一条消息。预期：员工不用追问基础信息。
2. 明确要求它"先提问确认再动手"。预期：它先列出 2–3 个澄清问题，而不是直接开干。
3. 验收时不对就具体指出哪一段要改。预期：按点修改，而不是整篇重写。
4. 聊久了留意"上下文用量"。预期：接近上限时能看到用量提示。
5. 需要时点"压缩上下文"。预期：界面给出类似"正在压缩上下文…"的提示，随后出现"上下文摘要"，对话继续、原文可回看。

**怎么验证成了**：连续 3 轮对话里，员工不再问已经给过的信息；压缩后它能准确引用压缩前的约定。

**常见问题**：

- Q：压缩之后它像忘了约定？A：打开"上下文摘要"核对那条约定在不在；不在就手动补一句"我们继续按之前说的……"。详见 RB08"压缩后答非所问"。
- Q：怎么看以前聊过什么？A：侧边栏"历史记录"和员工会话列表里翻，员工会话保留每个员工的主对话轨迹。
- Q：Code Mode 员工的会话能手动压缩吗？A：不能，ACP 代理管理的会话暂不支持手动压缩。
