# RB04 组建 Team 出活

> 本文是通用机制 runbook；界面入口与文案以你的客户端为准，配套参考实现见 [implementations/openclaw/](../../implementations/openclaw/MAPPING.md)。

**一句话目的**：把多名数字员工编成一个 Team，一条消息同时派给所有人，按并行或串行拿到每个人的产出。

**适用场景**：任务能拆成几块同时做，或要按"先 A 后 B 再 C"的流水线处理。

**前提准备**：每名成员都是已创建、可正常对话的数字员工（先走 RB01）；成员数量不超过上限（以你客户端里的实际限制为准）。

**操作步骤**（入口名称以你客户端里的实际入口为准）：

1. 进入 Team 入口，新建 Team 并起个名字。预期：Team 创建成功，出现在列表里。
2. 把要参与的员工逐个加为成员。预期：成员列表显示所有已选员工。
3. 选派发模式：并行（parallel）所有人同时开工；串行（sequential）按顺序执行，上一步输出自动拼进下一步输入（超过 2000 字会截断）。预期：模式保存成功。
4. 在 Team 会话里发任务消息。预期：并行模式下每个成员各自开始回复；串行模式按成员顺序逐个产出。
5. 观察每个成员的气泡和状态徽章。预期：所有成员状态落定后，拿到每个人的产出。

**怎么验证成了**：并行——每个成员的会话里都有针对同一任务的独立回复；串行——最后一名成员的产出里引用了前序成员的结果。

**常见问题**：

- Q：某个成员显示"不可用"？A：该员工处于未启用/未激活状态，先去"数字员工"里启用，再重新派发。
- Q：串行模式下后面成员没开工？A：前序步骤失败会导致后续跳过；先修前序成员的问题再重发。
- Q：整条消息被拦了？A：安全检查是"通过全派发、阻断全阻断"，把请求改写清楚用途后整条重发（见 RB08）。
