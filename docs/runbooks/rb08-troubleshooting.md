# RB08 常见故障排查

> 本文是通用机制 runbook；界面入口与文案以你的客户端为准，配套参考实现见 [implementations/openclaw/](../../implementations/openclaw/MAPPING.md)。

**一句话目的**：按症状自查最常见的问题，多数 30 秒内自己修好；修不好也知道该带什么信息找支持。

**适用场景**：网关连不上、员工没响应、技能装了没生效、消息被安全策略拦截、压缩后答非所问、Code Mode 员工表现异常。

**前提准备**：能打开"设置"页；记得出问题的大概时间。

**排查步骤**（对号入座，从上到下）：

1. **网关连不上**：界面给出类似"网关未运行"的提示（参考实现文案）。→ 先等 10 秒看是否自动启动；不行去"设置"里手动启动；再不行点"修复"（以你客户端里的实际入口为准）。预期：网关状态恢复"已连接"。
2. **员工没响应**：发消息没回音，或界面提示类似"数字员工未激活"（参考实现文案）。→ 去"数字员工"列表确认状态是"已启用"，进员工会话等"正在唤醒数字员工"完成后再发。预期：正常收到回复。创建与验证见 RB01。
3. **技能装了没生效**。→ 核对运行时分组：Code Mode 员工只消费 codeagent 条目，默认模型员工只消费 openclaw 条目；再确认 Skill 是"已启用"且配置已保存。预期：重发后技能被调用。详见 RB02"关键概念"。
4. **消息被安全策略拦截**：发送后界面提示类似"被安全策略拦截"（参考实现文案）。→ 这是安全中心的消息级检查拦住了它（Team 里"通过全派发、阻断全阻断"）；把敏感操作改写成白话说清用途再发。预期：改写后通过。
5. **压缩后答非所问**。→ 打开"上下文摘要"核对关键约定有没有被保留；没有就手动重申约定，或点"压缩上下文"再压一次；还不行就新建对话。预期：恢复对约定的记忆。对话技巧见 RB03。
6. **Code Mode 员工表现异常**：任务没走编码代理、或会话里完全没有思考/工具调用过程流。→ 三步核对：① 员工详情里的运行方式确实显示 Code Mode（参考实现的 Lite 版本默认锁定 Code Mode，界面有提示）；② 技能装的是 codeagent 条目组，不是 openclaw 组（见第 3 条）；③ 把任务改小重试一次。预期：任务按编码代理方式执行，过程三段流可见。具体操作见 RB05。

**怎么验证成了**：对应症状的复现操作不再报错，员工行为恢复正常。

**联系支持时带上**：客户端版本号（设置里查看）、出问题的员工名和 Team 名、出错时间点与截图、网关状态、你的账号环境。信息越全，定位越快。

**常见问题**：

- Q：什么情况必须找支持？A：上面 5 步都试过仍不行，尤其是网关反复重启失败。
- Q：聊天记录会丢吗？A：历史会话保留在员工会话里；压缩只摘要化原文，原文仍可回看。
