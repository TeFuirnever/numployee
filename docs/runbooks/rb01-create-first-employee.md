# RB01 创建你的第一个数字员工

> 本文是通用机制 runbook；界面入口与文案以你的客户端为准，配套参考实现见 [implementations/openclaw/](../../implementations/openclaw/MAPPING.md)。

**一句话目的**：从一个角色模板"转化"出一个能陪你聊天的数字员工，并完成第一次对话。

**适用场景**：第一次使用支持数字员工的客户端，想要一个属于自己的专属助手，而不只用默认的虚拟默认助手。

**前提准备**：客户端已登录；侧边栏"网关状态"正常。若显示"网关未运行"，先等它自动唤醒，或去"设置"里启动网关。

**操作步骤**（入口名称以你客户端里的实际入口为准）：

1. 在侧边栏点"数字员工"，进入后点"新建员工"。预期：弹出"新建数字员工"窗口。
2. 填写员工名、职业等基本信息，挑一个角色模板作为底子。预期：必填项都填完，确定按钮可点。
3. 在描述里写清"它是谁、怎么说话、负责什么"。预期：保存后回到员工列表，能看到新员工。
4. 在列表里对该员工点"启用"。预期：状态变为"已启用"。
5. 点开侧边栏"员工会话"，选中这名员工，发一句"你好，介绍下你自己"。预期：收到符合你描述风格的回复。

**怎么验证成了**：员工列表里它的状态是"已启用"；员工会话里能收到回复，且语气和描述一致。验证不了，先看 RB08 的"员工没响应"。

**常见问题**：

- Q：它和我侧边栏里的"虚拟默认助手"有什么区别？A：虚拟默认助手是系统自带的默认助手，展示主会话历史，不能编辑、不能删除；新建的数字员工才是你自己的，可编辑、可装技能。
- Q：创建时报"Code Mode 与默认模型只能二选一"？A：二者互斥，选一个就行，详见 RB05。
- Q：保存时提示插件需要重启网关？A：按提示确认重启，等网关恢复后员工自动可用。
