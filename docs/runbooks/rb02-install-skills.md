# RB02 给数字员工安装技能

> 本文是通用机制 runbook；界面入口与文案以你的客户端为准，配套参考实现见 [implementations/openclaw/](../../implementations/openclaw/MAPPING.md)。

**一句话目的**：从 SKILL市场 给员工装上 Skill，并确认它真的会用了。

**适用场景**：想让员工获得写文档、查资料、操作工具等新能力。

**前提准备**：网关已启动；知道这名员工是"默认模型"运行还是"Code Mode"运行（员工详情里可看）。

**关键概念（先看这个）**：能力清单分两组——openclaw 条目供默认模型员工消费，codeagent 条目供 Code Mode 员工消费。启用时只消费与员工运行时匹配的那一组，装错组的表现就是"装了没生效"。这是通用分组机制：技能按运行时来源分组，客户端只挂载与员工当前运行时同组的能力。

**操作步骤**：

1. 点侧边栏"SKILL市场"，搜索想要的 Skill。预期：出现结果卡片。
2. 点"安装"。预期：界面给出类似"Skill已安装并启用"的提示（参考实现文案）。
3. 若该 Skill 需要密钥，打开它的"配置"页填 API 密钥或环境变量，点"保存配置"。预期：界面给出类似"配置已保存"的提示（参考实现文案）。
4. 回到员工详情，查看能力清单里该 Skill 是否为"已启用"。预期：技能出现在清单中。

**怎么验证成了**：给员工发一条必须用到该技能的消息（如让文档技能生成一份纪要），回复里出现技能调用痕迹。验证不了，看 RB08"技能装了没生效"。

**常见问题**：

- Q：装完员工却说不会这个技能？A：八成是运行时分组不匹配——Code Mode 员工只认 codeagent 条目，默认模型员工只认 openclaw 条目。
- Q：提示"网关还没启动，暂时加载不了技能"？A：先启动网关，再刷新技能页。
- Q：更新 Skill 要重启网关吗？A：界面给出类似"更新需要重启网关"的提示时按确认即可，重启期间对话会短暂中断。
