# 什么是数字员工？——写给第一次接触的你

> 本文是通用机制科普；配套参考实现见 [implementations/openclaw/](../../implementations/openclaw/MAPPING.md)。

> 全程你只需要记住一个比喻：**数字员工 = 你新招的一位真人同事/下属**。

先想象一个画面：周一早上，一位新同事来报到。他有名字、有工牌、有岗位手册，人事部还附了一份他的性格说明。你带他到自己的办公室，跟他讲清楚你习惯怎么协作，然后交代第一件活。第二天他来上班，还记得昨天聊到一半的事。——数字员工就是这位同事，只不过他的"肉体"是一段运行在电脑里的 AI。

## 一句话定义

**数字员工（Employee）是一个持久的、有名字的、有性格有专业能力、记得住事、能持续干活的 AI 同事。**

和网页上那种"问一句答一句、关掉页面就谁也不认识谁"的聊天机器人不同，数字员工更像一个真人：他有名字、有性格、有岗位手册、有一间自己的办公室和文件柜（workspace——存着他做过的活、记过的事）。你今天交代的事，他明天还记得；你上周提过的偏好，他不会让你重复第二遍。

在数字员工系统里，你看到的客户端本质上就是这家"公司"的办公楼；你招进来的每一位数字员工，都坐在侧边栏的树视图里，随时待命（闭源产品实现文案：一个 macOS / Windows 桌面客户端）。

## 它到底能做什么

别把它想成"高级版搜索引擎"，把它想成一个已经培训上岗的同事。他手里有一整份技能清单（闭源产品案例：技能库 47 门"职业技能课程"），随时可以按需"进修"。比如：

- **帮你把活从头干到尾**：在 GitCode 上挑一个 issue，从读需求、写代码、提交、推送，到回复评审意见、逐条改完标记解决——全流程不用你插手（技能 `gitcode-pr-review-and-fix`）。
- **像资深同事一样审你的 PR**：逐行挑毛病、看测试够不够、对照需求规格检查有没有做偏（`gitcode-pr-review`、`code-review`）。
- **诊断模糊的大毛病**：你只说了一句"整个客户端变慢了"，他不会瞎猜，而是顺着执行路径一步步追下去，找到真正慢的那一行（`diagnosing-bugs`）。
- **打包安装包**：把 Electron 应用打成 macOS / Windows 安装包，出了打包报错能系统性地排查（`packaging-helper`）。
- **做调研、写材料**：联网查资料、整理成报告（`research`）；干完活还会顺手把文档归档收拾干净（`repo-pedant`）。
- **"逼"你把需求想清楚**：你随口说"帮我做个功能"，他会像最较真的产品经理一样反复追问，直到需求变得可执行（`grilling`）。
- **交接班不打折扣**：一个员工干到一半，可以把进度、坑、下一步写成结构化交接单，下一个接手的同事（或你自己）拿着就能无缝续上（`handoff`）。
- **画图和做设计**：手绘风格的架构图、流程图、界面草图，也能出（`excalidraw-diagram`、`frontend-design`、`handdrawn-architecture-diagram-huawei`）。
- **当老师带你上手**：把代码库讲成课程，生成带练习的学习材料，适合带新人（`teach`、`scaffold-exercises`）。

一句话：你出目标，他出全套打法。而且他会"诚实且温暖"——不会为了讨好你而硬说瞎话，也不会在你犯错时装看不见。

## 数字员工和 agent harness 的区别

这可能是新手最容易绕晕的地方，我们慢点说。

**harness（载体/运行时）是公司提供的那套"雇佣体系和办公环境"**：身体（能运行 AI 的基础设施）、办公系统、考勤、工具调度、记忆机制。数字员工则是**坐在工位上的那个人**——他的人格（`SOUL.md`）、岗位纪律（`AGENTS.md`）、学过的技能、掌握的知识、和你相处出来的关系。

| 对比项 | harness（办公环境） | 数字员工（那个人） |
| --- | --- | --- |
| 是什么 | agent 运行时（如 OpenClaw）+ 支持数字员工的客户端 | 人格 + 纪律 + 技能 + 知识 + 关系 |
| 类比 | 公司大楼、工位、门禁、考勤机 | 坐在工位上、有名字有性格的员工 |
| 可以有几个 | 一套 harness 可以载多个数字员工 | 一个数字员工绑定一个运行时身份 |

几个关键事实：

- **一套 harness 可以载多个数字员工**：这就是 Team（班组/项目组），一个班组里多个员工可以并行干活，也可以排成流水线。
- **换 harness，人可以带走**：数字员工的"人格档案"就是几份 md 文档（由系统同步到持久 workspace，参考实现中为 `~/.openclaw/workspace/`），可移植。打个比方：公司搬家了（换电脑、换运行时），员工不用重新招聘——把他的档案盒抱过去，摆上新工位，他还是那个他，记得你、记得活、记得你们约好的规矩。

所以请记住这句话：**harness 是雇佣体系和办公环境，数字员工是坐在工位上的那个人。**

## 数字员工由什么构成——那几份 md 文档各是什么

真人同事有性格、有工牌、有员工手册；数字员工的这些，就是一份份 md 文档。模板由系统作为受管块同步到员工的持久 workspace（该产品的受管块同步机制：模板在其提示词增强模板目录中，由产品主进程中的受管块同步器（当前 v5.4.0）同步到 `~/.openclaw/workspace/`）。

**员工个人档案：**

| 文件 | 比喻 | 实际作用 |
| --- | --- | --- |
| `SOUL.md`（模板 `soul-enhancement.md`） | 性格与价值观 | 人格、语气、边界、信任模型：诚实且温暖、温和但有立场、培养你的独立判断、察言观色、主动伙伴、自然表达、边界感 |
| `AGENTS.md`（模板 `capabilities-enhancement.md`） | 岗位手册 + 员工守则 + 安全红线 | 操作指令、MCP 纪律、完成规则、认知纪律，含 "Session Startup" 和 "Red Lines"（运行时安全红线）标题 |
| `TOOLS.md`（模板 `tools-enhancement.md`） | 工具台账与环境笔记 | 本地 MCP/环境事实与配置链提示 |
| `IDENTITY.md` | 工牌 | 最小身份记录：名字、角色定位 |
| `USER.md` | 服务对象画像 | 最小用户档案，让他知道在为谁服务 |
| `BOOTSTRAP.md` | 入职首日指引 | 首次运行时的 MCP 调试提示 |
| `HEARTBEAT.md` | 考勤心跳 | 会话状态跟踪文件，由运行时生成（非本系统托管） |

**公司级配套**（下表以闭源产品案例的公司级配置为例，各实现可有自己的等价布局）：

| 仓库位置 | 比喻 | 实际作用 |
| --- | --- | --- |
| 根 `AGENTS.md` | 公司规章制度 | 编码规范（禁 any / 空 catch、界面文案强制走 i18n）、TDD、交付门禁、commit 规范、高风险区域管控 |
| 产品仓库的技能库 | 培训体系 / 职业技能课程 | 闭源产品案例：47 门技能，grilling、tdd、code-review、diagnosing-bugs、research、packaging-helper 等 |
| 产品的 AI 导航 wiki | 企业 Wiki 知识库 | index、项目架构、环境、IPC 约定、MCP 控制面、踩坑教训 |
| `docs/` | 企业档案室 | 架构文档、ADR、bug-fix 记录、how-to、教程 |
| 产品的领域术语表 | 统一术语表 | 全公司统一的概念定义 |

一个容易忽略但重要的设计：**子代理（subagent）只继承 `AGENTS.md` 和 `TOOLS.md`**。所以关键规则必须写进 `AGENTS.md` 而不是 `SOUL.md`——就像新员工培训，安全守则要进教材，人格魅力不能替代制度。

## 它是怎么跑起来的

把"招聘到上岗"的流程走一遍，你就全懂了：

1. **Role（角色模板）= 招聘 JD / 岗位说明书**。定义层：岗位名称、描述、指令、推荐模型。注意：JD 本身不能干活——贴一张招聘启事不会有产出。
2. **Employee（数字员工）= 入职报到的人**。Role 被持久实例化为一个具体员工，绑定一个 backing Agent，具备可对话的运行时状态。默认一个角色对应一个员工实例。员工有来源标记：自建（user）、市场下载（market）、系统预设（builtin）。
3. **Agent = 公司分配给他的独立办公室**。运行时的真实隔离执行单元，有独立 workspace 和 agentDir，是员工的运行时载体——你对话的目标是员工，不是那间办公室。

再看几个"部门"：

- **Team（班组 / 项目组）**：多个员工的命名组合，消息可并行（parallel）或串行（sequential）派发；成员是员工实例，session 完全隔离（`team:{teamId}:{agentId}:main`），V1 没有 leader，大家平级协作。
- **市场（员工市场）**：角色模板的分发渠道——可以下载别人培养好的员工模板（source = market），也可以发布自己培养的。
- **Code Mode（外聘专家模式）**：员工改由 ACP 编码代理（codeagent/opencode）承载的运行模式，与默认模型互斥。干活时你能实时看到它的思考、每一步工具调用和最终结论，过程全透明；代价是这类会话不能手动压缩上下文（参考实现中 Lite 版本默认启用该模式）。
- **Bastion（安保处）**：消息级安全检查——员工的每条消息先过安检再放行。
- **Gateway（能力层 / 工具调度中心）**：员工能用什么工具、调什么能力，统一从这里出去。
- **Usage 条目**：角色/员工声明的可安装能力清单，分 openclaw 条目（默认模型员工用）和 codeagent 条目（Code Mode 员工用）两组。
- **虚拟默认助手**：侧边栏树视图里的默认接待节点，展示 main Agent 的历史会话——相当于公司前台，是你进门见到的默认接待员。

**走一遍完整招聘流程**：想招一位"公众号写手"？先在市场上逛逛有没有现成的写手模板（Role），有就下载（source = market）、没有就自己写一份 JD；实例化之后，一位名叫"某某"的写手员工就入职了，系统自动给他分配一间独立办公室（Agent）；第一天他会照 `BOOTSTRAP.md` 做入职调试，之后就正式接活。想让写手和配图师搭班？把两人拉进同一个 Team，消息并行派发，各干各的、互不打扰。

## 和普通 AI 聊天（网页版 ChatBot）的本质区别

| 维度 | 网页聊天机器人 | 数字员工 |
| --- | --- | --- |
| 身份 | 每次对话都是陌生人 | 持久身份：名字、性格、岗位 |
| 记忆 | 关掉页面就没了 | 持久记忆：workspace 文件里存着做过的事 |
| 能力 | 通用问答 | 可装配技能：闭源产品案例技能库 47 门课程按需挂载 |
| 治理 | 基本靠模型自觉 | 有红线（Red Lines）+ Bastion 安检 + 审计 |
| 协作 | 单打独斗 | 可多员工组队（Team），并行或流水线 |
| 复用分发 | 无法带走 | 人格档案是 md 文档，可备份、可上市场分发 |

一句话收尾：**聊天机器人是一次性问答，数字员工是你团队里一个记得住事、有纪律、有手艺、干得久的同事。**

## 新人第一步建议

不用一次搞懂全部。建议这样开始：先和虚拟默认助手聊几次，熟悉"交代目标 → 看他干活 → 提意见"的节奏；然后照着市场模板实例化第一个员工；等他干出第一件漂亮活，再回来重读本文——那时候每个比喻都会变得具体。如果哪里没看明白，别急着追问概念，先去用一次：手感，永远比术语先到位。
