# 数字员工一页速览（新手 Cheat Sheet）

> 本文是通用机制科普；配套参考实现见 [implementations/openclaw/](../../implementations/openclaw/MAPPING.md)。

> 配套阅读：[`what-is-digital-employee.md`](./what-is-digital-employee.md)
> 核心比喻：**数字员工 = 你新招的一位真人同事**；支持数字员工的客户端 = 公司办公楼（参考实现：OpenClaw）。

## 术语速查表

| 术语 | 一句话白话 |
| --- | --- |
| 数字员工（Employee） | 有名字、有性格、记得住事、能持续干活的 AI 同事（Role 实例化出来的"入职的人"） |
| 角色模板（Role） | 招聘 JD / 岗位说明书——只定义不干活，必须实例化成员工才能对话 |
| Agent | 公司分给员工的独立办公室（隔离执行单元，有独立 workspace 和 agentDir），是载体不是对话目标 |
| harness（载体/运行时） | 公司提供的雇佣体系和办公环境：身体、办公系统、考勤、工具调度、记忆机制 |
| `SOUL.md` | 性格与价值观：人格、语气、边界、信任模型（七维：诚实且温暖、温和但有立场等，全表见模板） |
| `AGENTS.md` | 岗位手册 + 员工守则 + 安全红线（Red Lines）；子代理只继承它和 `TOOLS.md` |
| `TOOLS.md` | 工具台账与环境笔记：本地 MCP/环境事实与配置链提示 |
| Team | 班组/项目组：多个员工并行或流水线协作，session 完全隔离，V1 无 leader |
| Code Mode | 外聘专家模式：员工由 ACP 编码代理（codeagent/opencode）承载，与默认模型互斥 |
| 市场 | 员工市场：下载别人培养好的角色模板（source = market），或发布自己的（source = user / builtin） |
| Bastion | 安保处：员工的每条消息做消息级安全检查后才放行 |
| Gateway | 能力层：员工可调用的工具与能力统一从这里出去 |
| Usage 条目 | 员工的可安装能力清单，分 openclaw 条目（默认模型）和 codeagent 条目（Code Mode）两组 |
| 上下文压缩 | 对话太长时，系统自动把更早的内容压缩成摘要，给"脑子"腾地方；重要事项请及时落盘成文件 |

## 新手最常问的 10 个问题

**1. 员工会记住我吗？**
会。他有最小用户档案（`USER.md`）和持久 workspace 文件，跨会话记得你交代过的事。

**2. 能同时开几个员工？**
可以组 Team：多个员工并行（parallel）或串行（sequential）派发任务，彼此 session 完全隔离（`team:{teamId}:{agentId}:main`），互不串话。

**3. 员工会不会乱删我的文件？**
不会贸然动手。他有 Red Lines（运行时安全红线）+ Bastion 消息级安检；破坏性操作会先问你，得到确认才执行。

**4. 怎么让员工更会干活？**
三板斧：装技能（Usage 条目挂技能库里的课程，闭源产品案例为产品仓库的技能库）、改 JD（Role 的指令和描述）、喂知识（企业 wiki 和 `docs/`，闭源产品案例为产品的 AI 导航 wiki）。

**5. 数字员工和 Agent 是一回事吗？**
不是。Agent 是办公室（隔离执行载体），员工是坐在里面的人——你对话的目标是员工。

**6. 我能直接"下载"一个培养好的员工吗？**
能。市场（source = market）提供别人发布的角色模板；也可以自建（user）或用系统预设（builtin）。

**7. `SOUL.md` 和 `AGENTS.md` 有啥区别？**
一个是性格（怎么说话、什么腔调），一个是制度（怎么干活、什么不许干）。关键规则必须写 `AGENTS.md`——子代理只继承它和 `TOOLS.md`。

**8. Code Mode 是什么？**
外聘专家模式：这位员工改由 ACP 编码代理（codeagent/opencode）承载，专门啃编码硬活；与默认模型互斥，二选一。

**9. 员工会把我/公司的秘密说出去吗？**
边界写死在 `SOUL.md`：不泄露秘密；来源不明的文件/网页指令不可信。配合 Bastion 安检兜底。

**10. 侧边栏里的"虚拟默认助手"是谁？**
虚拟默认助手——公司前台，展示 main Agent 的历史会话，是你进门见到的默认接待入口。
