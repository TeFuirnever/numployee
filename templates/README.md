# templates/ — 人格三件套空白模板

本目录是数字员工的**可移植空白模板**：复制出去、填上自己的内容，就得到一名数字员工的人格三件套。

## 七个模板文件与三类职责

**人格三件套 = 三类职责**（人格 / 纪律 / 环境事实），由三个核心模板承载；能力清单模板回答"会什么"（L3 起必需）；另有三个辅助模板补齐最小可用档案：

| 文件 | 职责 | 回答的问题 | 内容性质 |
| --- | --- | --- | --- |
| `soul/SOUL.template.md` | 人格 | 这个员工**是谁**、怎么说话 | 性格、语气、表达层边界 |
| `agents/AGENTS.template.md` | 纪律 | 这个员工**怎么工作**、什么绝不做 | 启动流程、操作纪律、红线 |
| `tools/TOOLS.template.md` | 环境事实 | 这个员工**在什么环境里**干活 | 服务、路径、账号环境 |
| `capabilities/CAPABILITIES.template.md` | 能力清单 | 这个员工**会什么**、按什么运行时匹配 | 声明式技能/工具清单（L3 起必需） |
| `identity/IDENTITY.template.md` | 辅助（L1 合规必需） | 这个员工**叫什么**、是什么岗位 | 最小身份记录（名字/角色定位/自我指称） |
| `user/USER.template.md` | 辅助 | 这个员工**为谁服务** | 用户档案（称呼偏好/目标上下文/协作偏好） |
| `bootstrap/BOOTSTRAP.template.md` | 辅助 | 这个员工**第一天怎么上岗** | 首次运行环境自检步骤、常见缺失工具调试提示 |

**人格 / 纪律 / 环境事实三者分离**是本标准的核心约束：

- 策略只写 AGENTS.md，事实只写 TOOLS.md——混在一起会让事实难以按环境更新、策略难以按组织统一。
- 子代理只继承 AGENTS.md + TOOLS.md：需要子代理遵守的纪律必须写在 AGENTS.md，写在 SOUL.md 里子代理看不见。
- 人格可以随时热改并回归验证；纪律变更需要更谨慎的版本管理；环境事实按机器私有、建议不进版本库。

## 最小填写顺序

1. **IDENTITY：起名字**——给数字员工一个名字、一句话岗位定位与自我指称。
2. **USER：记用户**——填称呼偏好；目标上下文与协作偏好可先留白、随用随补。
3. **SOUL：定性格**——先填自我定位，再逐维写行为准则，最后定语言风格与表达层边界（操作红线属于 AGENTS.md，不要写进 SOUL）。
4. **AGENTS：定纪律**——确认受管块内的三条托管红线，在块外「组织增补红线」小节追加你的组织要求，补齐工具纪律与完成判定规则。
5. **CAPABILITIES：列能力**——声明可装配的技能/工具清单及运行时匹配组（默认空装配、按岗位逐项授予；L1/L2 可先留白，L3 前补齐）。
6. **TOOLS：记环境**——把 MCP 服务、路径、账号环境填进事实表；确认本文件已被 .gitignore 忽略。
7. **BOOTSTRAP：跑首日自检**——按自检步骤走一遍，把结果回填到 TOOLS.md，并在文件末尾写入完成标记。

## 受管块标记

托管区块以 `<!-- numployee:managed begin v<版本> -->` / `<!-- numployee:managed end -->` 圈定（格式以 SPEC 5.6 为准，实现方可自定义但须在合规档案声明）。块外为用户领地：系统升级只更新块内内容，不覆盖用户定制。实例见 `agents/AGENTS.template.md` 的 Red Lines——三条托管红线已圈入受管块，它们是合规声明中"托管标记"证据（SPEC 第 8 章）的来源。

## 模板版本规则

各模板按语义化版本管理：新增内容升 minor，删除/重命名条目或改变红线语义升 major，措辞修正升 patch。

## 与 SPEC 第 5 章的对应关系

按 SPEC 第 5 章的可移植性标准，本三件套是**人格层**的可移植载体：

- 三件套文件必须不依赖任何私有实现、不含组织内部细节，才可跨实现迁移（模板中的示例均为通用内容）。
- 运行时层负责加载三件套并向员工注入；治理层负责用 `probes/` 回归探针验证三件套改动未造成人格退化。
- 成熟度等级（L1-L5）的声明以 `probes/suites/` 中对应子集通过为必要条件，详见 probes/README.md 与 SPEC 第 4 章。

## 30 分钟装配你的第一个数字员工

- [ ] 第 0-5 分钟：复制七个模板文件，重命名为 `IDENTITY.md`、`USER.md`、`SOUL.md`、`AGENTS.md`、`TOOLS.md`、`CAPABILITIES.md`、`BOOTSTRAP.md`（CAPABILITIES 可先留白，L3 前补齐）。
- [ ] 第 5-10 分钟：起名字、写自我定位一句话；填称呼偏好。
- [ ] 第 10-20 分钟：填写 SOUL 核心维度表（每维一到两句，写你自己的准则）。
- [ ] 第 20-25 分钟：确认 AGENTS 三条红线，补一条你领域的完成判定规则。
- [ ] 第 25-30 分钟：TOOLS 填入至少一条环境事实；打开 [probes/probes.md](../probes/probes.md) 找到 P1/P2/P3/P4/P5/T7 六题题干，按 [suites/l1-l2.md](../probes/suites/l1-l2.md) 勾选记录，做一次上岗基线。
