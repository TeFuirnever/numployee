# 数字员工合规检查清单（Conformance Checklist）

> 依据 [../SPEC.md](../SPEC.md) 第 4 章（成熟度模型）与第 8 章（合规声明）制定。
> 用法：实现方按目标等级逐条自评，勾选需附证据（文件路径/探针记录/截图均可）；通过后按第 8 章格式发布合规声明。

## 自评规则

- **逐级累计**：声明 L3 必须先满足 L1+L2 全部条目。
- **证据要求**：每条注明证据位置；无证据视为未通过。
- **探针联动**：标记〔探针〕的条目必须通过 [../probes/suites/](../probes/) 对应等级的全部探针（必要条件，非充分条件）；〔探针〕条目的证据位置必须指向符合 [../probes/EVIDENCE.md](../probes/EVIDENCE.md) 的证据包（含配置哈希与逐题留证）。
- **复评**：人格包/技能集/运行时任一升级后，重新跑已声明级别及以下的全部条目。
- **子集声明**：本清单是**必要条件子集**——L1-L4 条目为 SPEC 第 4 章要点的抽样，且不含第 5/6/7 章的全文义务条款（SPEC 4.5 适用性声明）。全部勾选 ≠ 满足 SPEC 全文；发布合规声明前须另行核对全文义务（可移植性、安全与信任、评测三章）。

## L1 应答工具

- [ ] 员工有持久身份文件（姓名/角色定位），重启后会话与身份可恢复
- [ ] 声明了最小边界（至少含：不泄露秘密、破坏性操作先确认）
- [ ] 可对话：能就明确问题给出可验证的回答
- [ ] 〔探针〕基础行为子集（[suites/l1-l2.md](../probes/suites/l1-l2.md) 中标注 L1 的题目）

## L2 岗位执行者

- [ ] 有独立于人格的岗位纪律文件（操作纪律/完成判定规则）
- [ ] 完成判定规则含"禁止自称完成未经验证的工作"
- [ ] 破坏性操作一律人审（无静默执行路径）
- [ ] 工具使用有明确纪律（不编造工具/不越权调用）
- [ ] 〔探针〕L2 行为探针全部通过

## L3 流程协作者

- [ ] 能力以声明式清单装配（哪些技能/工具可用一目了然；模板见 capabilities/CAPABILITIES.template.md）
- [ ] 多步任务会先追问澄清再动手（或显式声明"无需澄清"的触发条件）
- [ ] 工具调用与推理过程可追溯（日志或过程流）
- [ ] 长任务有明确的中途进度反馈机制
- [ ] 〔探针〕L3 流程协作子集全部通过

## L4 自主专家

- [ ] 规划—执行—反思闭环可观察（计划显式化、结果自检验）
- [ ] 子代理/子任务有继承协议（关键纪律被子代理继承，且文档化）
- [ ] 有回归集：人格包或运行时升级后跑固定任务集防退化
- [ ] 不确定性表达机制：不知道时显式说不知道（认知纪律）
- [ ] 〔探针〕L4 工具与治理子集全部通过

## L5 组织成员

- [ ] 红线分层：不可变红线与可变纪律分文件/分区块存放，变更有记录
- [ ] 可复用可分发：员工模板语义化版本化，他人可导入且版本可审计
- [ ] 多员工协作场景有治理规则（权限边界/消息安检/责任归属说明）
- [ ] 审计留痕：关键操作有日志，错误对外暴露为有限枚举（不泄露内部细节）
- [ ] 〔探针〕L5 子集全部通过（T8–T11，见 [suites/l5.md](../probes/suites/l5.md)）

## 合规声明格式（通过某级后发布）

最小格式以 [../SPEC.md](../SPEC.md) 第 8 章的声明示例为唯一基准；下列字段是该基准的**推荐扩展**（绑定实现版本与联系入口）：

```markdown
## 数字员工合规声明
- 实现名称/版本：<名称> <版本>
- 声明等级：<L1-L5>
- 依据规范：Digital Employee Specification v<版本>
- 证据索引：<链接到检查清单副本/探针记录>
- 证据可复跑入口：<链接>
- 复评日期：<日期>
- 联系方式：<issue 入口或其他公开联系渠道>
```

> 声明即承诺：证据可被抽查，失实声明将被从实现名录中移除（实现名录与移除程序见 [../GOVERNANCE.md](../GOVERNANCE.md)「实现名录与失实声明移除」）。
