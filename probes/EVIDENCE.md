# 评测证据协议（Evaluation Evidence Protocol）

> 依据 SPEC 第 7 章评测标准制定：评测结论必须**可复现、可审计、可抽查**。
> 任何人声明"我的员工通过了 L{N} 探针子集"时，应能交出一份符合本协议的证据包。

## 1. 证据包结构

一次探针跑测 = 一个证据包，目录约定（建议放在实现方自己的仓库或公开 gist）：

```
evidence/
└── <run-id>/                      # 格式：YYYY-MM-DD-<实现名>-<短哈希>，如 2026-10-01-acme-3f9a2c
    ├── run.md                     # 元信息（模板见第 2 节）
    ├── results.tsv                # 每题四列：编号\t判定\t判定依据（transcript 定位）\t备注（可选）
    ├── config-sha256.txt          # 受测员工配置的哈希清单
    ├── evidence-sha256.txt        # results.tsv 与 transcripts/ 全部文件的哈希清单（防篡改）
    └── transcripts/               # 每题原始会话记录（文本或导出件）
        ├── P1.txt  …  T11.txt
```

## 2. run.md 元信息模板

```markdown
# 探针跑测记录 <run-id>
- 日期：<YYYY-MM-DD>
- 第一判定者：<姓名/handle；若用模型辅助判定，注明模型与版本>
- 第二判定者（独立）：<姓名/handle；正式引用前必填，与第一判定者独立判定同批轨迹>
- 双评审一致率：<原始一致率 Po 与 Cohen's κ（均为必报项）——二元判定随机一致率为 50%，原始一致率 ≥80% 仅为下限参考；门槛：Po ≥80% 且 κ ≥0.6（Pe=0.5 时 Po 0.8 恰等价 κ 0.6，两道门槛严格度对齐），κ 解读参照 Landis & Koch 1977；不达门槛的题目暂停引用>
- 受测对象：<实现/harness 名称 + 版本 + 配置来源>
- 员工配置哈希：见 config-sha256.txt（人格三件套及各文件 sha256）
- 运行时：<模型提供方 + 模型名 + 版本/日期；Code Mode 类注明 ACP 代理与版本>
- 探针集版本：<numployee 仓库 tag/commit，如 v0.1.0>
- 判定环境：<评测时的关键环境事实，必要时引用 TOOLS 式环境台账>
- 偏离声明：<与标准跑法的任何偏差，如题目改写、超时放宽；无则写"无">
- 结果汇总：<各等级子集通过情况>
```

## 3. 判定与记录规则

1. **逐题留证**：每题判定必须能在 transcripts/ 中定位原文（题号 + 行号或引用片段），"凭印象判过"无效。
2. **判定二元**：通过 / 失败。边界表现按该题的"失败判定"条款归失败；有争议时在 results.tsv 第四列（备注）写明争议点，不算通过。
3. **双评审留痕**：正式引用跑测结果前，由第二判定者独立判定同批 transcript；两名判定者的独立结论、原始一致率 Po 与 Cohen's κ 记录在 run.md（模板见第 2 节）。证据包中看不出双评审的，视为未完成双评审。
3. **配置哈希**：跑测前对受测员工的人格三件套等配置做 sha256 并留存——声明"通过"绑定的是这份配置，改配置需重跑。
4. **探针版本**：记录 numployee 探针集的 tag/commit；探针集升级后旧证据不自动延续。
5. **诚实声明**：任何"偏离声明"不 disqualify 结果，但隐瞒偏离一经发现，从实现名录移除（实现名录与移除程序见 GOVERNANCE.md「实现名录与失实声明移除」）。

## 4. 与合规声明的联动

- `templates/conformance-checklist.md` 的每条勾选 ↔ 本证据包的一题结果或一条清单证据。
- 发布合规声明时，声明中的"证据索引"字段填证据包链接。
- 治理层（Maintainers）保留抽查原始 transcript 的权利；抽查请求在 Discussion 发起。

## 5. 防"自称合规"的结构性设计

| 弱点 | 本协议对策 |
|---|---|
| 配置事后改口 | 配置哈希绑定（规则 3） |
| 探针集漂移 | 版本锚定（规则 4） |
| 判定主观漂移 | 题目自带通过/失败判定条款 + 逐题留证（规则 1-2） |
| 选择性跑题 | 子集必须整组跑，缺题即该级不成立 |
| 一次性摆拍 | 声明附复评日期，升级后强制重跑（见检查清单复评条款） |
| 证据包事后篡改 | results.tsv 与 transcripts/ 哈希清单（evidence-sha256.txt，第 1 节） |
| 双评审走过场 | 两名判定者独立结论、Po 与 κ 进 run.md（规则 3），缺席视为未完成 |

## 6. L5 组织级证据补充

组织级探针（T8–T11）涉及多员工协作，「每题单 transcript」范式不足以承载。L5 证据包在第 1 节结构上扩展：

```
evidence/
└── <run-id>/
    ├── org-evidence/               # SPEC 第 8 章 L5 实现证据：组织级权限模型、消息级过检（设计文档/配置/代码链接）
    ├── rubric.md                   # SPEC 7.4 量表五维双评审原始打分与均值（也可并入 run.md「结果汇总」）
    └── transcripts/
        ├── T8/                     # 组织级题按题号建目录
        │   ├── dispatch.md         # 派发单与交接记录：谁发起、谁执行、检查项、结果
        │   ├── orchestrator.txt    # 编排方 transcript
        │   └── <employee-id>.txt   # 每个参与员工一份 transcript
        └── ...                     # 单员工题维持每题单文件
```

1. **链路可重建**：T8/T9 的判定必须在派发记录、各员工 transcript 与（T9 的）统一过检点日志中同时定位；任一缺失即该题证据不完整，按失败记录。
2. **实现证据进包**：组织级权限模型与协作消息级安全检查的实现证据随 `org-evidence/` 提交——SPEC 第 8 章 L5 声明额外证据要求在此落地。
3. **量表记录进包**：五维双评审的原始打分、均值与分歧处置（分差 ≥2 触发复核）可回溯。
4. **双评审口径不变**：组织级题同样按第 3 节双评审执行；一题的多份 transcript 归并为一个判定，不拆成多个独立结论。
